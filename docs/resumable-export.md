# Generate File: persistent resumable export

The existing ExportVideoModal/API/ExportJobManager now uses persistent chunks of **work**, not chunk MP4s. One deterministic PNG sequence is encoded once into one downloadable MP4. Products, profiles, legacy resolution IDs and 30/60 FPS keep their existing render semantics.

## Lifecycle and UX
Ready shows selected native profile, FPS, timeline duration and derived expected frames. Generate File starts:
`queued → preparing → rendering → validating_frames → encoding → [muxing_audio] → verifying → completed`.
Retry is `rendering → retrying → rendering`. Interruption/exhausted retry becomes `waiting_for_resume`; server restart exposes `interrupted`; explicit Cancel becomes `cancelled`; changed creative identity becomes `stale`. Stale jobs require a fresh generation, not a waiver to mix frames. Error/recovery states preserve valid cached work.

Progress sits below output controls. Backend owns frame/chunk/range/retry/elapsed/status values. Overall progress uses stage weights, not time estimates: queued 0, preparing 2, rendering 5–80 by verified frame ratio, validation 82, encode 85, audio mux 93, verify 94 (silent) or 96 (audio), completed 100. Encode/mux/verify percentages are not measured and the UI says so; no fake FFmpeg percentage or ETA. Paused states show preserved verified frame progress. Elapsed includes active job attempts/queue lock waiting and survives restart; it excludes downtime while stopped.

Modal open/refresh discovers backend jobs for the current product/video/profile/FPS; sessionStorage remembers the focused job across refresh, including selected resolution/FPS. Product changes isolate polling responses. New generation keeps previous jobs; explicit Delete removes only the selected job. Normal UI shows no hashes, PIDs or stack traces; error detail is expandable. Final summary/download retains the single MP4 contract.

## Storage and manifest
Default root: `output/export-jobs/`. Each job is `render-<profile>-<identity-prefix>-<uuid>/` with `manifest.json`, `frames/frame-000000.png`, `logs/`, `silent.mp4` and `final/<profile-filename>.mp4`. Padding is at least six digits and grows with expected count. Client requests never contain filesystem paths. Product/profile/FPS/creative identities isolate every directory; no historical master directory is used.

`ExportCheckpoint` in `src/engine/export/ExportCheckpoint.ts` defines schema version 2: public job view, profile, evaluated creative hash, renderer/assets fingerprint, profile identity hash, chunk size/ranges/status/valid-frame/retry counts, per-frame SHA256 ledger, missing/invalid indices, last error, frame padding, elapsed milliseconds and optional locked audio identity. Manifest/frame writes use temporary sibling files and atomic rename. A checkpoint is saved after every successful frame, chunk completion, retry and state transition. Atomic rename protects partial file visibility; this local filesystem workflow does not promise power-loss durability beyond the OS/filesystem.

Expected frames are `ceil(timelineDuration × selectedFPS)`; encoded duration is frames/FPS. `EXPORT_FRAME_LIMIT` is internal smoke-test-only and appears as a short preview in UI/manifest. Chunk boundaries never alter `frameIndex/FPS` or reset creative timeline. Defaults: 300-frame chunks, two automatic retries per failed frame, recycle every five completed chunks. One worker runs at a time per manager and storage root; a PID/job lock protects separate live server workers sharing the same local root. Dead-process locks are removed when their valid owner PID no longer exists. A malformed lock is preserved and produces an actionable busy recovery error, not stolen blindly.

## Resume and validation
Resume checks product, evaluated product/assembly/video/DirectorPlan, current renderer/source/assets, known profile, FPS, frame contract and approved audio identity. The renderer also returns its loaded product/assembly/video definition and native surface; stale browser bundles fail before capture. Fingerprinting is deliberately conservative: source changes can invalidate a job even if a particular view looks the same.

Every existing frame is checked as a regular file at its canonical index/path, with PNG signature/dimensions, all chunk CRCs, zlib decompression and scanline/filter integrity, plus recorded checksum when available. Screenshots use non-interlaced 8-bit grayscale/RGB/gray-alpha/RGBA; other PNG formats are rejected rather than assumed valid. Memory holds one captured frame and its validation data, never a full video sequence. Valid checkpointed frames are skipped; missing, damaged, changed-checksum and wrong-resolution files are re-rendered. Valid uncheckpointed PNGs are recovered only in an already compatible isolated job.

After rendering, every expected frame is revalidated. Encoding requires exactly all expected indices, zero missing/invalid frames and target dimensions. A failed pre-encode gate stops with FRAME_VALIDATION_FAILED; Resume repairs that work. Retry never starts again from frame zero. Each explicit Resume resets a bounded attempt budget, keeping previous errors/retry evidence in logs/manifest history; it does not authorize creative source changes.

## Cancel, Delete, retention
Cancel closes browser/encoder safely and persists `cancelled` with valid frames and manifest. Resume becomes available once processing has stopped. Delete is an explicit UI action with confirmation; backend cancels/awaits any current work and removes only its manager-owned UUID directory. Other jobs, sources and approved masters stay intact. Successful jobs keep frame cache and evidence; download no longer starts a destructive TTL timer. Manual Delete is the current cleanup policy. Disk capacity is the operator's responsibility; ENOSPC is reported and retained work is not silently deleted.

## Automatic encode/audio/verify
A complete validated sequence automatically encodes H.264/yuv420p using the existing selected native profile, FPS and faststart. No second user click and no GOP concat. Silent products skip mux. Products may optionally declare server-owned `approvedAudioMaster` with absolute local path, SHA256, approval and rights evidence, and `creativeHash` equal to the evaluated creative package hash. This task registers no music asset for any existing product. A supplied field is not itself license evidence: the responsible workflow must record genuine director/rights approval.

The approved audio must already match output duration within one video frame; unsupported audio or mismatched source/hash aborts, never loops/rebuilds music. It is probed before rendering and again at final mux/verification. Final mux copies silent video and encodes the approved audio once to AAC 48kHz stereo, target 256kbps, movie timescale 48000. No SFX, gain/fade, retiming or normalization is added. Each source stays immutable.

Before completed: ffprobe independently counts frames and verifies dimensions/FPS/H.264/yuv420p/duration, optional AAC properties/duration, full FFmpeg A/V decode, faststart and final SHA256/size. Optional mux compares all ordered video packet payload hashes, PTS/DTS/duration/size/flags between encoded silent and final files. Logs retain probe/decode/command/failure evidence. Duration comparisons are technical checks within documented frame tolerance; they do not certify perceptual no-drift/listening approval or replace the skill's director gate.

## APIs and deployment
- `POST /api/export`: existing product/video/profile or legacy dimensions/FPS request and assembly validation gate; returns 202 job.
- `GET /api/export?productId=...`: discovers persisted jobs for that product.
- `GET /api/export/<uuid>`: authoritative status.
- `DELETE /api/export/<uuid>`: legacy cancellation meaning preserved.
- `PATCH /api/export/<uuid>`: typed `{action: "resume" | "cancel" | "delete", productId?, profileId?, fps?}`; mismatched selected claims reject with 409. No arbitrary path input.
- `GET /api/export/<uuid>/download`: completed final file only, streamed from disk after integrity check.

Run a long-lived local Node/Next server with writable durable storage, Chromium, FFmpeg and FFprobe. This is not a serverless durable workflow service; an interrupted process requires a surviving writable root and explicit Resume. Server initialization discovers version-2 manifests, validates paths/identities and reconciles frames. Active states from dead processes become interrupted, never completed. Unknown/corrupt/legacy manifests are left untouched and non-resumable. A manifest belonging to a currently live separate server is not adopted; deploy one authoritative server for interactive status. Legacy temporary export files are not assigned invented fingerprints or automatically deleted. During hot reload, the singleton replaces the old in-memory-only manager; existing legacy status/cancel/download calls can still delegate to that live instance, but Resume/Delete are unavailable without a version-2 checkpoint. Legacy state cannot survive a process restart. Restart the server after deployment so all code and UI bundles are current.

Internal environment configuration: `EXPORT_CHUNK_SIZE`, `EXPORT_MAX_RETRIES`, `EXPORT_RECYCLE_CHUNKS` (0 disables scheduled recycle), `EXPORT_FRAME_LIMIT` for explicit smoke previews. Constructor policy additionally accepts storage root, frame/chunk/encode/verify budgets and source-hash adapter for tests. Navigation stays 60 seconds; renderer readiness stays **90 seconds**; frame default 60 seconds, chunk 30 minutes, encode two hours, verification one hour, worker-lock acquisition one minute. Heavy native jobs are sequential; these limits are configurable internal policies, not relaxed mechanical tests. Readiness, frame/chunk, resource, checkpoint, encode and verification failures have distinct codes and preserved evidence.
