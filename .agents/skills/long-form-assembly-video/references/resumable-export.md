# Resumable export policy
Use for long videos at any resolution, including 720p, and high-resolution exports. A short export may use one chunk. Chunk = work range, not independently encoded MP4. Use one continuous native PNG sequence and one final encode; no audio per chunk.

## Operation
1. Confirm approved creative scope and gates. Freeze evaluated product/assembly/video/DirectorPlan plus renderer/assets source fingerprint, profile, dimensions and FPS. Capture approved audio identity if applicable. Do not recreate music for another resolution.
2. Generate a job with configurable chunk size (default 300 frames). Select smaller work ranges for expensive frames or tighter checkpoint/recycle needs; do not alter creative timing. Default one worker, not parallel 4K chunks. Plan inclusive contiguous ranges covering 0 through expectedFrames−1 exactly; time is frameIndex/fps.
3. Persist the versioned job manifest atomically. Record identities, expected timing/count, ranges/statuses, frame checksums, missing/invalid work, retries, stage, timestamps/elapsed and output paths. Checkpoint each successful frame, chunk completion, retry and stage change. Write temporary PNG then rename; release its buffer before next frame.
4. On interruption/restart, load and validate the manifest, reject legacy/unidentified/incompatible jobs and reconcile disk. Validate each actual PNG CRC, compressed scanlines, dimensions, index/path and checksum when checkpointed. Recover valid uncheckpointed files only inside the same compatible isolated job. Missing/corrupt/wrong-size files are repaired; never use file existence as validity.
5. Resume only compatible work. Source/profile/FPS changes trigger RENDER_CHECKPOINT_INCOMPATIBLE and a fresh job. Use bounded per-frame retries and structured readiness/frame/chunk errors. Recycle after failure and at configured chunk intervals; restore deterministic sources/native surface and verify browser-loaded data. Keep all valid frames when retry budget exhausts. Manual Resume grants a new bounded attempt budget.
6. Cancel stops processing and retains manifest/frames. Delete requires an explicit isolated job action. Keep cache through final QA and, by default, until manual Delete. Refresh rehydrates from backend; server state is authoritative. A local long-running Node server is required; process interruption is recovered through persistent jobs, not hidden automatic completion.
7. Automatically validate the full sequence when final required frame is written. Require exact count, contiguous indices, zero missing/invalid and native dimensions before encoding. If validation fails, STOP; Resume reconciles and repairs work. Encode once, mux an explicitly approved locked audio master once if present, then full decode/probe/hash/faststart and applicable stream-identity verification before COMPLETED. No audio means no artificial mux stage.
8. For native high-resolution output run a short representative smoke/resource test first. If unreliable, preserve work and report RENDER_RESOURCE_LIMIT; no infinite retries or disguised upscale. Return complete artifact or explicit resumable/blocked package with truthful stage/count/progress and logs.

## Repository implementation
See [Generate File infrastructure](../../../../docs/resumable-export.md) for manifest schema, API, configuration, retention and deployment limits. The machine manifest is generated by the typed backend, not manually from a template. This skill's [freeze manifest template](../templates/pre-render-freeze-manifest.json) records creative approval; job manifests record operational progress. Both are needed and serve different purposes.

STOP codes: RENDER_RESOURCE_LIMIT, RENDER_CHECKPOINT_INCOMPATIBLE, FRAME_VALIDATION_FAILED, ENCODE_FAILED, FINAL_QA_FAILED. Do not label skipped render/listening tests PASS.
